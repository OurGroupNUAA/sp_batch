# `results` Directory Guide

This directory contains the benchmark instances and algorithm outputs for the AlgorithmDP project. The data is primarily used to compare the exact Dynamic Programming (DP) algorithm, the DP' heuristic, and the Gurobi MILP model.

## Directory Structure

```text
results/
├── benchmark_instances/  # Benchmark instances and per-instance solver results
├── detailed_results/     # Detailed per-instance results for each algorithm
├── summary_results/      # Parameter-grouped statistics and algorithm comparisons
└── README.md   # This guide
```

## `benchmark_instances/`

This folder contains the `.txt` benchmark instances generated by `scripts/generate_instances.py`. There are currently 1,350 instances divided into three size categories:

| Size | Number of files | Number of jobs `n` | Batch capacity `b` |
| --- | ---: | --- | --- |
| small | 450 | 5, 10, 15, 20, 25 | 2, 3, 4 |
| medium | 450 | 100, 200, 300, 400, 500 | 7, 9, 11 |
| large | 450 | 1000, 2000, 3000, 4000, 5000 | 13, 15, 17 |

Each parameter group also contains combinations of `gamma = 1/95/190` and `rep = 1–10`.

Instance filenames follow this format:

```text
instance_<ID>_<size>_n<number_of_jobs>_b<batch_capacity>_g<gamma>_rep<repetition>.txt
```

For example:

```text
instance_00001_small_n5_b2_g1_rep1.txt
```

Each file mainly contains:

- Instance parameters: `instance_id`, `n`, `b`, `gamma`, `q`, `s`, `rep`, and the random seed `seed`;
- Job data: each row records a job ID `id` and its processing time `p`;
- Solver results: the objective value, runtime, and status for DP, DP', and Gurobi. These results are written to the end of the instance file when a solver script is run with `--backfill-txt`.

The parameter `gamma` is the lower bound used when randomly generating processing times `p`. By default, `q` is generated from 1 to 5, while `s` is generated from 1 to 10.

## `detailed_results/`

This folder contains detailed per-instance results in CSV format. Each row corresponds to one instance in `benchmark_instances/`, making these files suitable for result tracing, algorithm verification, and custom statistical analysis.

| File | Description | Current records |
| --- | --- | ---: |
| `dp_py_detailed.csv` | Objective values, runtimes, and statuses from the exact DP algorithm | 1,350 |
| `dp_prime_detailed.csv` | Objective values, runtimes, and statuses from the DP' heuristic | 1,350 |
| `gurobi_small_detailed_py.csv` | Detailed Gurobi MILP results for the small instances | 450 |

Common fields in these files include the instance filename, `n`, `b`, `q`, `s`, `rep`, and `seed`. Each algorithm also records:

- `*_obj`: objective value (makespan `C_max`);
- `*_time`: solution time in seconds;
- `*_status`: solution status, such as `OPTIMAL`, `TIME_LIMIT`, or an error message.

## `summary_results/`

This folder contains statistical tables aggregated from the results in `detailed_results/`. They can be used directly to prepare paper tables, performance reports, or charts.

| File | Description |
| --- | --- |
| `table_dp_py_summary.csv` | DP results grouped by `(n, b, q)`, including average objective value, average runtime, and solution counts |
| `table_dp_prime_summary.csv` | DP' results grouped by `(n, b, q)` |
| `table_gurobi_small_py_summary.csv` | Gurobi results for small instances grouped by `(n, b, q)` |
| `table_dp_comparison_medium_large.csv` | Comparison of DP and DP' on the medium and large instances |

The main fields in the first three summary tables are:

- `avg_obj`: average objective value among instances with an `OPTIMAL` status;
- `avg_time`: average runtime among instances with an `OPTIMAL` status;
- `solved`: number of instances solved to optimality;
- `total`: total number of instances in the parameter group.

The DP comparison table is grouped by `(n, b, gamma)` and contains:

- `T_DP` and `T_DP_prime`: average runtimes of the two algorithms;
- `N_gap`: number of instances for which DP' and exact DP return different objective values;
- `G_max`: maximum absolute objective-value gap within the group;
- `RPD_max_pct`: maximum relative percentage deviation within the group;
- `instances`: number of instances in the group.

## Usage Guide

- To inspect the input data and solver outputs for a specific problem, see `benchmark_instances/`.
- To examine an algorithm's performance on individual instances, see `detailed_results/`.
- For overall performance analysis or table generation, start with `summary_results/`.
- `.DS_Store` is directory metadata automatically generated by macOS. It is unrelated to the experimental results and can be ignored.

For data-generation and solver commands, see the `README.md` in the project root.
